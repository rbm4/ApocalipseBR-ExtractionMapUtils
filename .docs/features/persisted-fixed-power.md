# Persisted managed generators

Status: implemented; dedicated-server/stock-client runtime validation pending.

`ApocExtractionMapUtils_FixedPowerAreas.lua` queries the V48 shape of `mod_data.fixed_power_area` on each dedicated-server startup, using ApocalisebrPack's server entity facade. It is independent of `LobbyEnabled`/`LobbyFixedPower`. The mapping `Extraction.ManagedGenerator` has `(server_id, world, area_id)` IDs and scalar `enabled`, `x`, `y`, `z` fields. Java captures the configured server ID and save-world name, executes prepared SQL on the existing worker and returns entity objects through OnTickEvenPaused.

Enabled rows become `ApocBRManagedGenerators.registerGenerator("persisted-generator:<area_id>", x, y, z)`. The entire returned collection is validated before admission; duplicate IDs/tiles and invalid coordinates are rejected. Failed admission rolls back earlier definitions from that batch. Limits remain 256 returned rows/255 enabled database definitions, reserving a possible lobby slot within the manager's total 256. It is admission of desired sources, not a synchronous guarantee that native objects already exist. Java logs READY after instantiation/reconciliation and handles chunk loading, save/reuse, protection and full fuel/condition.

The normal startup query retries BUSY/UNAVAILABLE/DATABASE_ERROR every five seconds, up to five attempts and 120 seconds. Terminal success, failure or timeout calls `finishStartup()`. Unknown saved managed generators are suspended while the catalog is pending, then removed if no matching definition exists. Late database callbacks do not apply records. Disabling/deleting a source takes effect on the next startup, including cleanup when its old chunk subsequently loads. No live refresh or purchase workflow is implemented.

V48 archives all old rectangles in `mod_data.fixed_power_area_legacy_v47`. Only single-tile V47 rows migrate automatically; other entries need explicit source coordinates. Apply V48 and the updated mod/patch together. The [backend contract](../../../apocalipsebr-manager/manager/docs/fixed-power-areas.md) owns schema/grants/SQL; the [engine guide](../../../apocalipsebr-zomboid-patches/42.22.2/docs/features/2026-11-11-fixed-power-regions.md) owns native lifecycle and authority. [Lobby generator configuration](lobby-fixed-power.md) remains separate.

Operational prefixes: `[ApocExtractionFixedPower]` for queries, counts, tile registrations, rollback and startup result; `[ApocBRManagedGenerators]` for native instantiation, status, protections and removal; `[ApocExtractionManagedGenerator]` for rejected normal timed actions. Reconciliation preserves normal generator coverage/effects and stock network formats, with no rectangle power-getter override or custom client class.

Fengari `tests/fixed-power-areas.lua`, `tests/lobby-power.lua`, and `tests/managed-generator-protection.lua` passed. Native Java production-method fixtures, entity-bridge fixtures and the real isolated PostgreSQL migration tests passed separately. Still validate actual Kahlua loading, paused startup, source materialization, save/restart, reconnect, chunk boundaries, ordinary generators and stock-client electrical devices. The former protocol-gap report is historical evidence explaining this refactor, not the current runtime architecture.

All admitted source definitions now enter the same bounded Java pre-warm queue as the lobby generator. The manager explicitly renews the zombie-cleanup `keepCellLoaded` bridge until integration, then validates the floor/obstructions and creates the source. It does not depend on natural loading during initial setup; see the [validation/pre-warm hotfix](../hotfixes/managed-generator-validation-and-prewarm.md).
